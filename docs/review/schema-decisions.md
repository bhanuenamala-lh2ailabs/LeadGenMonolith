# Schema review - decisions and disposition

Reviser's answer to `schema-critic-A.md` (production quality / canonical model) and `schema-critic-B.md` (legacy fidelity / downstream needs).
Nothing had been applied to `db/leadgen.sqlite` (it still does not exist), so migrations `0001`-`0014` were edited in place; the migration set is still
`0001..0014` and the first real `migrate` will apply the corrected files.  Everything was re-verified from zero on throwaway databases under
`db/_scratch/` (deleted afterwards): `migrate`, `PRAGMA integrity_check`, `PRAGMA foreign_key_check`, `doctor()`, `pytest` (130 tests), the legacy generator
`--check` (all 9 files byte-identical to what the generator renders), and a full verbatim load of all 9 legacy databases (3,331,980 rows, 904 MB scratch,
doctor `ok`, the only FK findings being the 2 known radar orphans).  Performance was measured on 60k deals / 209k events.

Legend: **FIXED** as the critic proposed - **FIXED (changed)** fixed, but not exactly as proposed (why given) - **DOCUMENTED** a rule the importer / operator must follow,
written where the importer will read it - **NOT FIXED** with the reason.

| H1 | Timestamp CHECK `LIKE '____-__-__T__:__:__%Z'` validates nothing; `ist_day` NULL | **FIXED (changed).** All 121 timestamp CHECKs now use `col IS strftime('%Y-%m-%dT%H:%M:%fZ', col) AND col NOT GLOB '*T24:*'` (round trip through SQLite's own parser; one expression instead of GLOB + strftime; the extra `T24` clause closes the one hole found: `24:00:00.000Z` survives the round trip). Rejects every row in A's table plus `2026-02-30`, second precision, 9 fractional digits, `+05:30Z`, lower-case `t`/`z`. `ist_day` is `NOT NULL` on `deal_stage_event`, `deal_owner_event`, `engagement`. `valid_to` / `window_end` use `IS`; `window_end >= window_start` added.
